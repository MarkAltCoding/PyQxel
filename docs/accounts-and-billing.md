# Accounts and Billing

Every `/api/v1` request is made by an account, identified by its PyQxel API key in `Authorization: Bearer <key>` (or `X-API-Key`). Only a hash of each key is stored. Accounts pay for their own usage, and nothing one account does is billed to another or to the server:

* **Signing in**: anyone can make an account by signing in with GitHub or Google, when the server [has them set up](setup.md#signing-in-with-github-and-google), or with an email and password, when it [can send email](setup.md#signing-in-with-an-email-and-password). Accounts are matched by the provider's permanent ID for the person and by their verified email, so a GitHub and a Google account with the same verified address sign in to the same PyQxel account, as does an account made before with `python -m app.jobs.users create` and a password set by a link emailed to that address. No address joins an account before it is proven: a password is chosen only on the page its emailed link opens. Signing in gives the browser an API key that expires after `SIGN_IN_KEY_DAYS` (30 by default), unless it is in use: the website and the app trade a key more than a day old for a fresh one (`POST /api/v1/auth/renew`, the old one working five more minutes). Signing out revokes it sooner, while keys created for scripts keep working and never expire. Each sign-in deletes the account's revoked and expired sign-in keys.

* **AI analyses** run on the account's own Anthropic key, and **market data** comes from Financial Modeling Prep on its own FMP key. An optional **Alpha Vantage** key fills the gaps: it answers market data requests (quotes, prices, company profiles, exchange rates) when FMP fails or the account's FMP plan does not cover them, fills in profile fields FMP leaves empty (`filled_fields`), and supplies financial statements the SEC filings leave out (see [fundamentals](models.md#fundamentals-and-valuation)). It works on a [free key](https://www.alphavantage.co/support/#api-key), which allows 25 requests a day and one a second: answers are reused for up to a day (a minute for quotes), requests are spaced a second apart, and only the statements covering missing items are requested. The free plan covers quotes, financial statements, exchange rates and symbol search, but not the company overview, adjusted prices, or intraday bars, so on a free key: profiles have a name, currency and price but no sector, industry, or market cap (valuation then estimates the market cap from shares outstanding), and filling in profile fields FMP leaves empty is skipped; price history is the latest 100 daily bars, not adjusted for splits or dividends, with a `notice` saying so (with `YFINANCE_FALLBACK` on, yfinance's full adjusted history is used instead); and intraday bars return 402. `pytest --live` checks the key in `ALPHA_VANTAGE_API_KEY` against the real service, using about nine requests. An optional **Finnhub** key, whose [free plan](https://finnhub.io/register) is enough, supplies [company news](models.md#company-news) and [analyst ratings, earnings, and insider trades](models.md#analysts-earnings-and-insiders); it is also the first source of quotes for US listings (real time, at 60 requests a minute, where FMP's free plan quotes only a sample of symbols), the second source of company profiles after FMP, and fills in profile fields FMP leaves empty. Its free plan has no price history, so prices still need FMP or Alpha Vantage. Finnhub requests are kept to 55 a minute per key, shared through Redis when it is set, and a request the plan refuses is not repeated for a day. `pytest --live` checks the key in `FINNHUB_API_KEY` against every Finnhub endpoint used, with eight requests. PyQxel never stores these keys. The website keeps them in the browser, on the Settings page, and sends them with every request; scripts do the same, each key in its own header: `X-Anthropic-Key`, `X-Tiingo-Key`, `X-FMP-Key`, `X-EODHD-Key`, `X-Alpha-Vantage-Key`, and `X-Finnhub-Key`. Each kind of market data tries the account's keys cheapest first, so a free [Tiingo](https://www.tiingo.com) key covers US price history in full, and [EODHD](https://eodhd.com) adds indices and listings abroad; the Settings page shows, for each kind, which keys cover it and what adding another would unlock. The server uses them for that request only and scrubs them from logs and error messages ([`app/core/redact.py`](../app/core/redact.py)); `GET /api/v1/me` reports which keys the request carried, by their last four characters. Any subset of keys works: the Settings page lists what each missing key turns off, and pages show what is missing in place of the data. Without an Anthropic key, analyses return 403; without an FMP or Alpha Vantage key (and with the development fallback off), market data returns 403, and a request the account's FMP plan does not cover returns 402.
* **Stored results**, meaning backtests, analyses, and simulations, belong to the account that made them; listing, reading, and deleting see only its own. Reports are never reused across accounts, and a provider's data cached for one account is not served to accounts without their own key for that provider.
* **Limits**: each account can cap its new AI analyses with `PUT /api/v1/me/limits` (`{"ai_requests_per_hour": 10, "ai_requests_per_day": 50}`, `null` for no cap); reused reports are free and do not count, and `GET /api/v1/me` shows recent usage. Every account may also make `RATE_LIMIT_PER_MINUTE` requests a minute (120 by default) across the API, counted in Redis when it is configured.
* **API keys**: create more with `POST /api/v1/me/api-keys` (`{"name": "laptop"}`; the key is shown once), list them with `GET /api/v1/me/api-keys`, and revoke one with `DELETE /api/v1/me/api-keys/{id}`. If an account loses every key, `python -m app.jobs.users add-key you@example.com` issues a new one.
* **Deleting an account**: owners delete their own, with everything it holds, under Delete account in Settings or with `DELETE /api/v1/me`. For a deletion request from someone who can no longer sign in, run `python -m app.jobs.users delete them@example.com`, which asks before deleting (`--yes` skips the question).
* **Paying for the nightly refresh**: see [below](#paying-for-the-nightly-refresh). Everything else costs the server almost nothing, so it is free.
* **Browser security**: the app's pages are served with a Content-Security-Policy that runs only the app's own scripts and allows requests only to its own origin, since the browser keeps the API key in local storage. The native app runs under the same policy (`web/src-tauri/tauri.conf.json`), allowing requests only to its server, and keeps the API key and provider keys out of web storage: in the Keychain on iPhone (this device only, readable after its first unlock) and in a file only the account can read on a Mac, written to disk before the app goes on, so closing or killing the app never loses them. It renews its 30-day sign-in key while in use, as the website does. The threat model is at the top of `web/src/lib/secureStorage.ts`.

## Paying for the nightly refresh

Using PyQxel costs its server almost nothing: requests take milliseconds, and each account's keys pay the data providers. The one thing that costs real money is the [nightly refresh](models.md#each-users-own-screener), which keeps a Cloud Run job running for minutes (the S&P 500) to hours (every US stock and ETF). With Stripe set up (`STRIPE_SECRET_KEY` and `STRIPE_WEBHOOK_SECRET`; see [Google Cloud Run](setup.md#google-cloud-run)), users pay for their refreshes at cost, with nothing added:

* **What a refresh costs**: its share of the job's time at Cloud Run's rates for the job's CPU and memory (`JOB_CPU_SECOND_USD`, `JOB_GIB_SECOND_USD`, `NIGHTLY_JOB_CPUS`, `NIGHTLY_JOB_MEMORY_GIB`), split among the refreshes running at once. One vCPU and 1 GiB cost $0.072 an hour, so the S&P 500 costs about a cent a night and every US stock and ETF about 29 cents. A failed refresh is billed too, since the job ran.
* **Stripe's fees are the user's**, so no user costs the server's owner anything ([`app/billing/fees.py`](../app/billing/fees.py)): a top-up charges Stripe's fee on top ($10.61 for $10 of credit), and a card issued outside the US has Stripe's extra 1.5% taken from its credit once the card is known. Each subscription bill gets a line for its own fees while it is still a draft (`invoice.created`): 30 cents plus 2.9% for the card, Stripe Billing's 0.7%, and 1.5% more for a card from abroad or one whose country cannot be read. A dispute charges the account Stripe's $15 fee, and a disputed subscription bill is owed again; a won dispute gives the money back. Checkout leaves out the payment methods Stripe prices differently from a card, and charges in dollars only.
* **Prepaid credit**: any amount from $5 to $500 on a Stripe Checkout page, added when Stripe's webhook reports the payment. Each refresh uses it up.
* **Usage subscription**: Stripe bills what the refreshes cost each week, month, or year, after any credit; PyQxel reports each refresh's cost to a Stripe meter every hour (`python -m app.jobs.billing report` does it by hand). Settings shows what each choice would add in fees at the user's pace. Stripe charges nothing under 50 cents, carrying a smaller bill to the next.
* **No run goes past the credit.** Without a subscription, a refresh starts only when the credit covers what it is expected to cost (the most any of the user's last five refreshes cost, or half an hour of the job before the first), and one that still reaches the credit is stopped there, so the credit never goes below zero for usage and there is no debt to escape by deleting the account. Scheduled picks are held to the same rule. The Screener, its Refresh schedule tab, the picks schedule, and Billing each warn when the next run would not be covered. With neither credit nor a subscription, the refresh pauses until the user adds one; the rest of PyQxel is unaffected.
* **Claude's work is not billed by PyQxel.** Stock reports, portfolio reviews, Claude's Picks (scheduled ones included), and the coding assistant run on the user's own Anthropic API key, which Anthropic bills at its prices, or, for a prompt copied into Claude in the browser, on the user's Claude plan. Market data keys are billed by their providers.
* **Managing payments**: changing a card, invoices, and canceling are on Stripe's customer portal. Refunds and disputes of a top-up take its money back out of the credit, a top-up a card network flags as likely fraud is refunded at once, and deleting an account ends its subscription at the end of the period and refunds the credit left. The site's [terms of service](/terms) and [refund policy](/refunds) pages say the same to users. Checkout runs without Stripe's Managed Payments, which would add its own fee to every payment and does not allow the fee line on subscription bills.
* **Sales tax and VAT** come from [Stripe Tax](https://docs.stripe.com/tax), once its settings are active in the Dashboard (Tax → Settings: a head office address and a default tax behavior of exclusive), which the server checks every hour. Checkout then asks for a billing address and adds the tax due on top of the price, but only in the places added as registrations under Tax → Locations; registering with each tax authority is the owner's to do. The products carry the tax code for SaaS for personal use (`txcd_10103000`, set by `app.jobs.billing setup`). The tax is never credit, and Stripe's fees on it, with Stripe Tax's 0.5% where it collects, are the user's like its other fees; a refund of a top-up returns the tax paid on the refunded credit.
* **No payments from the EU or UK**, which tax digital services from the first sale with no threshold for a seller abroad (`CLOSED_COUNTRIES` in [`app/models/billing.py`](../app/models/billing.py)). A top-up's card is only held at Checkout (`capture_method: manual`); the webhook then captures it, or releases it at no cost when the billing address or the card is from there, and a subscription started from there is canceled before its first bill. Either way the account is marked (`billing_accounts.closed_country`) and offered no other payment.

`GET /api/v1/me/billing` reports the credit, subscription, recent cost, and history; `POST /api/v1/me/billing/top-up`, `/subscription`, and `/portal` return a Stripe page to send the browser to. Payments are made on the website: an App Store build of the app shows billing without a way to pay.
